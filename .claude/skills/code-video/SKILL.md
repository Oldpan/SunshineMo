# Code-generated video

Everything lives in `video/` (see `video/README.md`):
- `core/` is style-agnostic and shared by every series.
- `series/<name>/` holds one look plus its music recipe and narrative pattern. It contains `style.py`, `template/`, `episodes/` and a README with the rules.

Series so far (table in `video/README.md`):
- `neon_science`: neon nebula, EDM, energetic.
- `warm_journal`: paper journal, lo-fi, emotional.

`video/tools/` has `sheet.py` (contact sheet of stills) and `glyphs.py` (tofu check).

**Before starting, read the series README of the series you are working in.**

## Default constraints (unless the user says otherwise)

- **Generated from code only.**
  - Every frame comes from code.
  - Never download images, footage, fonts, samples or audio files.
  - Music is synthesized from oscillators and noise only: no samples and no virtual instruments.
  - System fonts are fine.
- **Format:** 1920×1080 at 60 fps, H.264 at 14 Mbps plus AAC 256k. 2–4 minutes unless asked.
- **No voiceover:** cuts follow the music (bars, kicks, drops), and the story is told through captions and graphics.
- **Language:** Chinese for this user. Go from theory to real Chinese everyday examples, and label examples as illustrations, not data.
- **Facts:** cite real papers and put the references in the end card and the episode README. Never invent numbers.
- **Never show the production brief** in the film (no "made with code / no samples" line); it belongs in the README only.
- **Delivery:**
  - Send the mp4 in chat (SendUserFile).
  - Upload to Google Drive folder `video_from_opus` with `python3 scripts/gdrive_upload.py <file> --folder video_from_opus`, then check that the returned `size` equals the local byte count. Details are in `docs/google-drive-api.md`.
  - Commit the code, never the `out/` directory.

## Choosing where to work

| Request | Do |
|---|---|
| Another video in an existing series | `cp -r video/series/<s>/template video/series/<s>/episodes/<name>` and grow it. Scripts find `core/` and `style.py` themselves. |
| A different look or genre | Create `video/series/<new>/` with its own `style.py`, `template/` and README, and add it to the table in `video/README.md`. Reuse `core/`; copy from an existing `style.py` only what fits. |
| Unsure which series | Ask the user. Each series is a deliberate style; don't silently drift one into another. |
| "Change the style" with no style given | Offer 2–3 concrete directions with AskUserQuestion previews (palette, fonts, motifs, music genre and BPM, mood) and recommend one. |

### Style contract

A series `style.py` exposes an object with two methods, which `core.pipeline.run(style.frame, style.setup, dur, fps, out_dir, name)` drives:
- `setup()` runs once per worker. Load the shaders, surfaces and random tables there.
- `frame(fi)` returns raw RGB bytes. It usually does this:
  1. `x = Ctx(t)`
  2. `pic = tl.record(x, t)` (the shots)
  3. background
  4. content
  5. fx
  6. post-processing (`core/post.py`)

Shots push per-frame knobs through `Ctx`: `chroma`, `shake`, `split`, `zoom`.

## Workflow

1. **Topic and facts.** Pin down the claims, numbers and references first.
2. **Storyboard by bars.** Write a section table (bars → music → picture) into the episode README. At 100 BPM a bar is 2.4 s.
3. **`music.py`.**
   - Compose with `core.synth`: `Song`, `make_buses`, the instruments, `mixdown`, `export`.
   - This writes `out/music.wav` plus `out/sync.npz` (event times and per-frame envelopes).
   - Seeds must come from `stable_seed()`, never `hash()`.
4. **`render.py`.**
   - Write one `@tl.shot(t0, t1, tin, tout, kin, kout)` per shot; transitions are zoom, fade, whip and cut.
   - Read the music with `S.pulse("kick", t)`, `S.since(...)` and `S.e("pad", t)`.
   - Vary the caption styles between shots.
5. **Check stills.**
   - Run `python3 video/tools/glyphs.py render.py cover.py <style.py>` first; it must report nothing missing.
   - Run `python3 render.py --still 3 15 30 ...`, including transition moments (the first 0.1 s of a cut, tape stops, drops).
   - Make a contact sheet with `video/tools/sheet.py` and look at it: overlaps, tofu glyphs, readability.
6. **Preview a range.** Run `python3 render.py --range a b --fps 30` (veryfast preset).
7. **Full render.**
   - Run `python3 render.py` in the background.
   - neon_science takes about 40 min for 3 min on 4 cores (the shader costs about 0.9 s per frame per core).
   - warm_journal has no shader and runs at about 7.6 fps, so 26 min for 198 s.
   - Monitor it; don't poll with sleep.
   - Verify with ffprobe that the frame count equals dur × 60 and that the duration is right.
8. **Covers.** Run `python3 cover.py` to get 16:9 (1920×1080) and 3:4 (1080×1440), then look at both.
9. **Publish.** Upload the mp4 and the covers, check the sizes, and send the files in chat.
10. **Publishing copy.** Offer 3–5 titles, a description (open with the viewer's inner monologue, then give the experiment and numbers, then the reassurance, then the references) and hashtags.
11. **Record what happened.**
    - Add a publishing record to the episode README.
    - Add the episode to the series table.
    - Fold new reusable code back into `core/` or `style.py`.
    - Append new lessons below.

## Lessons learned (append; newest last)

**Environment and tooling**
- skia-python needs `apt-get install libegl1 libgl1`. `skia.RuntimeEffect.MakeForShader(src)` returns the effect itself, not a tuple.
- SkSL uniforms are tightly packed float32s; a float3 is 12 bytes. Pass them as `np.array(list, np.float32).tobytes()` in declaration order.
- Full-resolution fbm shaders are too slow. Render the background at 384×216 and upscale; it is soft anyway.
- Inter has no CJK glyphs. Any string containing Chinese, such as "2024 年", must use `font(size)` (WenQuanYi) or it renders as tofu.
- Python's `hash(str)` is randomised per process. Using it for seeds made the music differ on every run; use `core.synth.stable_seed`.
- `core.pipeline` forces the `fork` start method. Workers inherit module globals such as the shots and `S`; `setup()` builds the unpicklable skia objects.

**Readability** (feedback on v1 of 好感差距: "looks like a haze, can't read the text")
- Keep caption glow alpha at or below 0.5.
- The bloom threshold should catch only real highlights.
- Never use constant chromatic aberration; only on hits.
- Put a dark halo (DropShadow) under the content layer.
- Keep the background dark with contrast (`pow 1.18`).
- Readable text matters more than glow.

**Effects**
- Users like more motion, as long as it never covers the text.
- Put sparks outside a radius of about 420 px.
- Every effect should be tied to a music event.

**Layout**
- Measure text before placing it next to rings, charts or bubbles.
- Put a dark panel behind small captions.
- Number labels on charts sit inside the bars, so dashed gap lines and flares never cross text.

**Encoding**
- 14 Mbps keeps a 3-minute film around 320 MB. v1 at an uncapped CRF was 865 MB.

**Metadata**
- ffmpeg writes only `encoder` tags (Lavf, Lavc, libx264) and the x264 SEI options. Nothing identifies AI unless we add it.
- Remuxing with `-map_metadata -1` (and `-fflags +bitexact`) strips the tags without re-encoding.

**Verification and process**
- When refactoring an episode onto shared code, render stills (including glitch and impact frames) and covers before and after, and require `max |diff| == 0`. Compare the music md5 under a fixed `PYTHONHASHSEED`.
- Treat the user's mid-task messages as course corrections. Example: "more series later" led to the core/series split.

**warm_journal (lo-fi paper) lessons**
- On light paper never use additive (PLUS) glow or bloom; they wash the page out.
  - Give text `glow=0`.
  - Turn bloom on only for dark looks, scaled by `look["dark"]`.
  - Draw the paper texture with multiply *over* the content.
- Never let a palette glide between a light and a dark look. Halfway through, ink and paper have the same brightness. Put those sections in `fast` and hide the switch with a crash or film burn.
- A hard cut into a drop needs `kout="cut"` on the outgoing shot too. Otherwise it slides away under the new shot.
- Odometer digits (`text_roll`) mid-roll read as garbage ("71:65"). Use `spins=0` for clock times, and keep the roll at or below 0.3 s.
- Event sparkles go in the margin bands (top, bottom, far edges) only; a random ring around the centre lands on captions.
- Tape stop plus a true silence:
  - Apply `tape_stop` and then `gate_silence` to the mix *after* `mixdown`, so the reverb tail is cut too.
  - Add the vinyl crackle afterwards so it survives the silence.
  - A half-beat `reverse_swell` into the drop still leaves an audible gap.
- Vinyl crackle pops must be capped (about 0.1). Uncapped heavy-tailed clicks hit -0.3 dBFS.
- Covers: a half-torn calendar page reads as "330" when small. Use a clean page.
- Verify official statistics on the original page. stats.gov.cn returned 503 once, then served the page on retry. Media reprints are not a citation.
- Making a new style that a user picked from previews worked well. Show the reference contact sheet early if the user is around.
